# 06 · 填充引擎

> 代码入口：`src/content/`（页面内）、`src/core/fill.ts`（统一填充解析）、`src/background/index.ts`（统一填充服务）。

## 1. 统一填充服务：两个库共用一套填充体系

填充层不认识 Bitwarden / KeePassXC。popup 按钮与页面内浮层都只发出
「来源 + 条目 id + 字段」（`MSG.FILL_ITEM`），真实的值只在 background 中取出：

- 用户名、密码直接取自条目；
- 验证码统一解析为**即时验证码**：KeePassXC 经 `get-totp` 现取；Bitwarden 的 `login.totp`
  是 `otpauth://` 种子（旧条目可能是裸 Base32 密钥），由 `core/totp.ts` 按 RFC 6238 算出。

UI 层因此不持有密码：搜索结果经 `core/suggest.ts` 瘦身为 `Suggestion`
（名称 / 用户名 / 来源 / 是否有验证码），复制密码也只报条目（`MSG.COPY_ITEM`）。

## 2. 页面内填充浮层

- 挂在**封闭 Shadow DOM**：页面脚本读不到候选里的账号名。
- 输入框内图标 + 聚焦即弹出候选；支持方向键 / 回车 / Esc，并按已输入文字过滤。
  每行有「填充」「验证码」「复制密码」。
- 点条目填充账号和密码，同时把验证码复制到剪贴板（30 秒自动清空，S-5）。
- 验证码框内显示「OTP」图标：点一下填入或刷新验证码。
- 「打开网页时自动填充」是设置页的开关，且必须同时满足：该站点唯一匹配、账号密码框都为空、
  https、顶层页面。任一条件不满足只弹候选，由用户选择。

## 3. 站点授权（M-3）

不申请全站通配 host 权限。页面内填充有两种生效方式：

| 方式       | 行为                                                                   | 需要授权 |
| ---------- | ---------------------------------------------------------------------- | -------- |
| 默认       | 点过工具栏图标的页面，当页可用（`activeTab` 注入）                     | 不需要   |
| 按站点启用 | popup 里点「本站启用页面内填充」，之后打开该站点自动出现图标并自动填充 | 仅该域名 |

background 把内容脚本注册到「用户已授权的站点集合」上
（`chrome.scripting.registerContentScripts`），并在 `chrome.permissions.onAdded / onRemoved`
与 service worker 启动时同步。设置页会列出已授权的站点并可逐个撤销
（密码库服务端地址除外——撤销它会直接导致无法登录）。要像 Bitwarden 那样一次性全站启用，
需项目所有者先修订 M-2。

## 4. 保存密码

`src/content/save-watcher.ts` 以「**提交成功后的痕迹**」为信号——表单消失、被清空或路由跳转，
而不是点一下按钮就问。这样点「显示密码」、校验没通过都不会误报。

- 取值以用户最后一次输入事件为准：我们自己填充的、被站点脚本替换成哈希的值都不算新密码。
- `core/save.ts` 判定三种结果：新建 / 更新同用户名的条目 / 无需处理。
- 表单 `submit` 时先把草稿交给 background 暂存（`chrome.storage.session`，90 秒有效），
  整页跳转后由下一页接着提示。
- 草稿与密码始终留在 background；确认时只回传来源（`MSG.SAVE_DECISION { source }`）。

## 5. 字段识别

`collectCredentialInputs()` 遍历普通 DOM 与所有 `shadowRoot`，按 `type` / `name` / `id` /
`autocomplete` 分类为 `username` / `password` / `totp`。每类只取第一个字段，避免把密码灌进
"确认密码"框。两条增强：

- `type="email"` 直接视为账号框；
- 账号框没有任何提示性命名时，紧挨首个密码框之前的文本框视为账号框。

`isFieldVisible()` 排除不可见字段：隐藏的诱饵输入框不填，自动填充只针对看得见的表单。
`observeFields()` 用 MutationObserver 监听动态插入（SPA），防抖后重新定位浮层。

## 6. 填充纪律（S-4）

只做两件事：写 `input.value`，派发 `input` 与 `change` 事件。
禁止 `innerHTML`、`data-password`、`window.__vaultix` 等任何页面 JS 可读的凭证载体。
隔离世界里只有一个布尔标记用于防止脚本被重复注入，不含凭证。

> 教训（2026-11-25）：模拟出来的测试桩只能证明实现自洽，证明不了与真实协议兼容。
> 协议类代码要对着真实服务或官方向量验证——TOTP 用 RFC 向量，KeePassRPC 直连真实 KeePassXC。
